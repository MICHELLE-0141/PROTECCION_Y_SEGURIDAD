6.1 — FUNDAMENTOS · CAPÍTULO 9.1

Seguridad y protección: dos niveles

El libro llama seguridad al problema general de impedir accesos o cambios no autorizados, y mecanismos de protección a los controles específicos del sistema operativo.

A

Seguridad

Considera qué información proteger, de qué amenazas y mediante qué medidas técnicas, administrativas y organizativas.

Pregunta clave: ¿qué queremos proteger?

B

Protección

Son los mecanismos que establecen permisos sobre archivos, procesos y otros recursos del sistema.

Pregunta clave: ¿qué operación está permitida?

◎

Objetivos principales

Confidencialidad: evitar exposiciones; integridad: evitar cambios no autorizados; disponibilidad: evitar interrupciones. El capítulo también menciona impedir que programas externos tomen control del sistema.

Ejemplo cotidiano

En una computadora familiar, cada persona puede tener una cuenta. Los permisos pueden dejar que alguien lea un documento compartido, pero impedir que modifique los archivos personales de otra persona.

6.2 — AMENAZAS · CAPÍTULO 9.1

Objetivos y amenazas

El capítulo relaciona los objetivos de seguridad con las amenazas que pueden afectarlos.

01

Confidencialidad → exposición

Alguien sin autorización obtiene información privada.

◉
02

Integridad → alteración

Datos se modifican, eliminan o falsifican sin permiso.

△
03

Disponibilidad → denegación del servicio

Una acción impide que usuarios legítimos usen un servicio.

⏸
04

Control del sistema → virus

Un programa malicioso puede apropiarse de recursos del equipo.

◇
!

Otras situaciones

El libro distingue intrusos pasivos, que leen sin permiso, y activos, que intentan modificar datos. También considera pérdidas accidentales por fallas, errores humanos o desastres.

Cómo reconocer el objetivo afectado

Si alguien lee un expediente sin permiso, afecta la confidencialidad; si cambia una calificación, afecta la integridad; si satura el servidor de la escuela y nadie puede entrar, afecta la disponibilidad.

6.3 — MECANISMOS DE PROTECCIÓN · CAPÍTULO 9.3

Permisos para usar
los recursos

El modelo del libro organiza el acceso mediante procesos, dominios, objetos y permisos.

01

Proceso

Solicita acceso a un recurso bajo la identidad de un usuario.

02

Objeto

Recurso protegido: archivo, directorio, dispositivo o programa.

03

Dominio

Conjunto de objetos y operaciones accesibles al proceso.

04

Permiso

Operación autorizada sobre el objeto: leer, escribir o ejecutar.

!

Decisión de protección
El sistema comprueba si el dominio del proceso tiene el permiso solicitado para ese objeto.

Ejemplo de decisión

Un proceso solicita leer un archivo. El sistema identifica el proceso y su dominio, busca el permiso de lectura para ese objeto y permite o rechaza la operación según la matriz de protección.

6.4 — MATRICES DE ACCESO · CAPÍTULO 9.3.1–9.3.3

Una matriz, dos formas
de guardar permisos

Las filas representan dominios y las columnas, objetos. Cada celda indica las operaciones permitidas.

Ejemplo didáctico de matriz de acceso
DominioArchivo de notasImpresoraConfiguración
EstudianteLeerUsar—

AdministradorLeer / escribirUsarAdministrar

ACL, por columnas: cada objeto guarda quién puede acceder y con qué permisos.

Capacidades, por filas: cada proceso guarda objetos y operaciones que puede usar.

En la práctica: se almacenan permisos existentes para evitar una matriz enorme y vacía.

Los nombres y permisos de la tabla son un ejemplo creado para explicar la matriz.

Cómo leer la matriz

En la fila “Estudiante” y columna “Archivo de notas” aparece “Leer”: ese dominio puede consultar el archivo, pero no modificarlo. Una ACL guardaría esos permisos junto al archivo; una lista de capacidades los guardaría junto al proceso o dominio.

6.5 — PROTECCIÓN BASADA EN EL LENGUAJE · EJEMPLO DEL CAPÍTULO 9.8.7

Limitar código que llega
desde fuera

El libro usa Java y los applets como ejemplo de cómo el lenguaje y su entorno pueden restringir código no confiable.

comprobaciones de seguridad
código remoto
      ↓
verificar tipos y accesos
      ↓
ejecutar con permisos limitados

¿Qué mecanismos describe?

Java comprueba tipos y referencias. Un verificador revisa el bytecode antes de ejecutarlo; una caja de arena limita el acceso a memoria y recursos. Las firmas pueden ayudar a verificar el origen del código.

  • Rechazar usos incompatibles con los tipos.
  • Comprobar bytecode antes de ejecutarlo.
  • Restringir recursos con una caja de arena.

El libro describe tecnologías de su época; aquí se usan como ejemplo conceptual de protección basada en el lenguaje.

Ejemplo de caja de arena

Si un programa descargado intenta abrir documentos personales, la caja de arena puede bloquear esa operación y permitirle trabajar solo con los recursos autorizados.

6.6 — VALIDACIÓN Y AMENAZAS · CAPÍTULOS 9.1 Y 9.6

Entradas inesperadas
pueden abrir fallas

El libro explica ataques que aprovechan errores de programación. Validar las entradas ayuda a reducir algunos riesgos antes de procesar los datos.

↗

Desbordamiento de búfer

Una entrada mayor a la esperada puede sobrescribir datos en memoria.

⌁

Cadena de formato

Tratar una entrada como formato puede causar lecturas o cambios indebidos.

◌

Desbordamiento de enteros

Un cálculo fuera del rango previsto puede producir errores posteriores.

⊙

Escalada de privilegios

Un error puede dar permisos mayores a los que corresponden.

MEDIDA PREVENTIVA

Validar antes de procesar

Comprobar formato, tamaño y límites de los datos y revisar los permisos del programa. La validación ayuda, pero por sí sola no garantiza que el sistema sea seguro.

Validación en un formulario

Antes de guardar un archivo, un programa puede revisar que el nombre tenga un formato permitido y que el tamaño no supere el límite esperado. Así reduce entradas inesperadas que podrían activar errores de código.

6.7 — CIFRADO · CAPÍTULO 9.2

Convertir un mensaje
con una clave

La criptografía transforma texto simple en texto cifrado para que solo quien tenga la clave adecuada pueda recuperar el mensaje.

01 · TEXTO SIMPLEHOLA
→
02 · ALGORITMO + CLAVE🔑
→
03 · TEXTO CIFRADO••••
1

Clave secreta o simétrica

Usa la misma clave, o claves relacionadas, para cifrar y descifrar; hay que compartirla de forma segura.

2

Clave pública o asimétrica

Usa un par de claves relacionadas, una pública y otra privada. El capítulo también explica funciones de una vía y firmas digitales.

El algoritmo puede ser público; la clave debe protegerse. Una función hash no es cifrado reversible.

Ejemplo práctico

Al enviar información confidencial, el mensaje se cifra antes de transmitirlo y el destinatario autorizado lo descifra con la clave correspondiente. Una firma digital ayuda a verificar quién lo envió; un hash permite comparar integridad, pero no recuperar el texto original.

PARA RECORDAR

Proteger requiere
decisiones concretas.

La seguridad combina objetivos claros, permisos bien definidos, cuidado del código y mecanismos criptográficos.
